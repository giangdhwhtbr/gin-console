# Optional sign-in with config-managed users

Date: 2026-11-27
Status: proposed

## Context

gin-console is read-only and runs as one process on one host, normally on loopback behind `tailscale serve`. It has no authentication: anyone who reaches the port reads every project. Some operators now share it with several people and need to limit who sees which project, while single-user setups must keep working without a login. The console has no database, and `config.yaml` is written by hand.

## Decision

- Auth is off unless `auth.enabled` is true in `config.yaml`.
- Users live in a separate YAML file (`auth.users_file`), written only by a `python -m gin_console user ...` CLI, so `config.yaml` keeps its comments. The file has mode 0600, is written atomically, and is reloaded by the running console when it changes.
- Passwords are generated by the CLI (`secrets.token_urlsafe(18)`) and stored as stdlib scrypt hashes; there is no new dependency and no way to choose a weak password.
- Sessions are random tokens held in server memory and sent in an `HttpOnly`, `SameSite=Strict` cookie. A restart signs everyone out; logout and user changes end sessions at once. A signed stateless cookie was rejected because it needs a managed secret and cannot be revoked; HTTP Basic auth was rejected because it has no sign-out and puts a password check on every request.
- Failed sign-ins are limited in memory per username and per client IP.
- Access is a list of project names per user; a project outside it answers 404 like an unknown one. Caches stay shared per project and the check runs before them.

## Consequences

- One process only: sessions and rate-limit counters are not shared between processes, which matches ADR 0001.
- Behind a proxy that sends no `X-Forwarded-For`, every client shares one IP, so the per-IP limit becomes a global one.
- Every route that takes a project must use the allowed-projects resolver; a table-driven test lists them so a new route without it fails.
- Users choose no password of their own; the operator resets it with the CLI.
